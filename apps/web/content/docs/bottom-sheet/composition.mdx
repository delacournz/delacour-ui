A sheet is a root and the parts placed inside it. The root does all of the arithmetic — the
detents, the keyboard lift, where the footer sits — and publishes it through three contexts. A part
reads those and renders one thing, and every part accepts `style` and `ref`.

```tsx
import { BottomSheet } from "@delacour/react-native-bottom-sheet";

<BottomSheet>
  <BottomSheet.Trigger />
  <BottomSheet.Portal>
    <BottomSheet.Overlay />
    <BottomSheet.Container>
      <BottomSheet.Background />
      <BottomSheet.Handle />
      <BottomSheet.Content>
        <BottomSheet.Title />
        <BottomSheet.Description />
        <BottomSheet.TextInput />
        <BottomSheet.Close />
      </BottomSheet.Content>
      <BottomSheet.Footer />
    </BottomSheet.Container>
  </BottomSheet.Portal>
</BottomSheet>;
```

## The render tree

```txt
BottomSheet              the root — state, geometry, animation, the pans, the ref; renders nothing
  Trigger                anywhere in the app's tree; opens the sheet
  Portal                 the frame — teleported to the nearest host, or in place with `inline`
    Overlay              the scrim, written BEFORE the panel so hit-testing gives the panel its taps
    Container            the panel — the one view that moves
      Background         an absolute fill under everything; where the surface colour and radius go
      Handle             the grabber row; a pan detector and the sheet's one adjustable element
      Content            the static body; a pan detector; clamped to the area above the footer
        Title            labels the panel for assistive technology
        Description      supporting copy
        TextInput        a field the sheet owns the keyboard for
        Close            dismisses
      Footer             sticky over the body, riding the keyboard; or a plain view that scrolls
```

Exactly one body: `Content`, or one of the [scrollables](/docs/bottom-sheet/scrollables), or
[`Steps`](/docs/bottom-sheet/steps). `Footer` is written **beside** the body, not inside it, so it
can stay put while the body scrolls under it.

`Container` is the moving panel and `Content` is the static body. That is the naming the skinned
library uses too, so a sheet written against one reads against the other.

## The overlay is written first

Native hit-testing walks siblings back to front, so a touch on the panel never reaches the overlay
and a touch beside it does. The overlay is a React Native `Pressable`, never a Gesture Handler tap:
a full-screen tap gesture behind the sheet wins a touch on a `TextInput`, which has no gesture of
its own, and the field never focuses. Omit `Overlay` and the sheet has no scrim, and the app behind
it stays interactive.

## Context reaches every part

The three contexts are provided once, by the root. A teleported portal moves the **native** view
and leaves the React tree where it was, so they reach every part without being re-provided — and
so does every context your app provides around the trigger: a theme, a form, a query client.

```tsx
import { useBottomSheet, useBottomSheetAnimated } from "@delacour/react-native-bottom-sheet";
import Animated, { useAnimatedStyle } from "react-native-reanimated";

function Chevron() {
  const { index, snapToIndex } = useBottomSheet();
  const { animatedIndex } = useBottomSheetAnimated();
  const style = useAnimatedStyle(() => ({ transform: [{ rotate: `${animatedIndex.value * 180}deg` }] }));
  return <Animated.View onTouchEnd={() => snapToIndex(index === 0 ? 1 : 0)} style={style} />;
}
```

| Hook | Returns | Thread |
| --- | --- | --- |
| `useBottomSheet()` | `isOpen`, `setOpen`, `index`, `detentCount`, and every ref method | JS — React state, updated on settle |
| `useBottomSheetAnimated()` | `animatedIndex`, `animatedPosition`, `animatedHeight`, `containerHeight`, `handleHeight`, `contentHeight`, `footerHeight`, `keyboardLift`, `detents`, `closedHeight` | UI — shared values, for `useAnimatedStyle` |
| `useBottomSheetInternal()` | what the parts share, for a part written outside the package | |

Each throws outside a `<BottomSheet>`; the `useOptional…` form returns `null` instead.

## The ref

```tsx
const sheet = useRef<BottomSheetRef>(null);

sheet.current?.snapToIndex(1);
sheet.current?.snapToPosition("50%");
sheet.current?.expand();
sheet.current?.collapse();
sheet.current?.open();
sheet.current?.close();
sheet.current?.dismiss(); // close, under the name the library this replaces used
sheet.current?.forceClose(); // no animation
```

Every method is an intent: none animates from the JS thread, and each is a no-op when it makes no
sense — `close` on a closed sheet, `snapToIndex(4)` with two detents. `snapToPosition` clamps to
the available height and never adds a detent. `open` and `close` are the same state a controlled
`isOpen` drives.
