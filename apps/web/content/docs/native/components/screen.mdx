## Usage

```tsx
import { Screen } from "@delacour/native-ui/screen";
```

```tsx
<Screen>
  <Screen.Navbar>
    <Screen.Navbar.BackButton onPress={router.back} />
    <Screen.Navbar.Title>Settings</Screen.Navbar.Title>
  </Screen.Navbar>

  <Screen.ScrollArea>{children}</Screen.ScrollArea>

  <Screen.Footer>
    <Button onPress={save}>Save</Button>
  </Screen.Footer>
</Screen>
```

The navbar and footer measure themselves into a Reanimated context and every scrollable reserves
exactly that, so no screen carries a hand-tuned padding number.

## Placement

`overlay` floats the chrome over the content, which insets itself to match; `static` puts it in the
flow and paints an opaque surface.

```tsx
<Screen.Navbar placement="static">…</Screen.Navbar>
<Screen.Footer placement="overlay">…</Screen.Footer>
```

## Borders

Both hairlines are drawn at rest; `fadeBorderOnScroll` opts into a scroll-linked ramp instead — the
navbar's brightens as you leave the top, the footer's fades out as the content runs out.

```tsx
<Screen.Navbar fadeBorderOnScroll>…</Screen.Navbar>
<Screen.Footer fadeBorderOnScroll>…</Screen.Footer>
```

## Chat lists

`Screen.ChatList` is a discriminated union on `variant`: `legend` takes chronological oldest-first
data and LegendList's own `renderItem`, `flat` is an inverted `FlatList` with newest-first data and
React Native's.

```tsx
<Screen.ChatList
  composerBaseHeight={56}
  data={messages}
  renderItem={renderMessage}
  variant="legend"
/>
```

<Callout type="warn" title="Seed a chat list with composerBaseHeight">
The footer publishes its real height a commit or two after the list's first layout, and the list has
already scrolled to the end by then. Without the seed the newest message hides under the
composer — intermittently, which is the worst kind of wrong.
</Callout>

## Loading and error

Whole-screen states, each with its own navbar so a back gesture still works.

<Preview id="screen/loading-and-error" />

```tsx
<Screen.Loading title="Loading" />

<Screen.Error message="That project no longer exists." onBack={router.back} title="Not found">
  <Button onPress={retry}>Try again</Button>
</Screen.Error>
```

## API Reference

### Requirements

<Callout type="warn">
The app must mount [`DelacourProvider`](/docs/native/components/provider) at its root. `Screen`
reads the safe-area and keyboard providers, and `<KeyboardStateSync />` is what keeps the keyboard's
shared values honest between screens — without it a screen renders "keyboard open" over a keyboard
that is not there.
</Callout>

`@legendapp/list` is an optional peer, so an app that never imports `Screen` never resolves it.

### Parts

<Preview id="screen/a-pushed-screen" />

| Part | What it is |
| --- | --- |
| `Screen.Navbar` | Pinned top chrome. Compound: `.Title`, `.Subtitle`, `.BackButton` |
| `Screen.Content` | The content region between the chrome |
| `Screen.View` | A non-scrolling body |
| `Screen.Header` | A scrolling header inside the content region |
| `Screen.Footer` | Pinned bottom chrome, keyboard-aware |
| `Screen.ScrollArea` | A `ScrollView` with the reserves applied |
| `Screen.FlatList` / `.SectionList` / `.LegendList` | Virtualised lists, same reserves |
| `Screen.ChatList` | An inverted or oldest-first chat list |
| `Screen.Loading` / `Screen.Error` | Whole-screen states |

### `Screen.NavbarBackButton`

A `Pressable`, so the vocabulary is inherited. `onPress` is **required** — this library takes no
navigation dependency, so the app wires `router.back()` itself. There is no `Navbar.Action` either:
a navbar action is `<Button isIconOnly size="sm" variant="secondary">`.
