## Sizes

One axis drives five values: the height, the label's type scale, the icon step, the horizontal
padding and the corner. `--radius-button-*` is half each height, so a button is a capsule by
default and a square one a circle. Square one off with `className="rounded-lg"`, or retune the
three tokens to change every button at once.

<Preview id="button/sizes" />

```tsx
<Button size="sm">Small</Button>
<Button size="md">Medium</Button>
<Button size="lg">Large</Button>
```

The same axis carries the square sizes — see [Icon button](#icon-button).

## Icons

Icons are composed, not passed as props — put an `Icon` in the children, before or after the label.

<Preview id="button/icons" />

```tsx
import { Icon } from "delacour-react-native-ui/icon";
import { IconArrowRight, IconTrash } from "delacour-react-native-ui/icons/central";

<Button onPress={next}>
  <Button.Label>Continue</Button.Label>
  <Icon icon={IconArrowRight} />
</Button>

<Button variant="destructive" onPress={remove}>
  <Icon icon={IconTrash} />
  <Button.Label>Delete</Button.Label>
</Button>
```

The button publishes its size and its variant's foreground token to the subtree, so a bare `<Icon>`
comes out right with nothing said at the call site. An explicit `size` or `color` still wins.

## Icon button

Use an `icon-*` size for a square button whose only content is an icon. Each one is its labelled
step — the same height, corner and icon token — with the horizontal padding traded for a width off
that step's own token, so the footprint is square by construction rather than by two numbers
agreeing.

<Preview id="button/icon-button" />

```tsx
<Button accessibilityLabel="Favourite" size="icon-md" variant="ghost">
  <Icon icon={IconHeart} />
</Button>
```

`icon-sm`, `icon-md` and `icon-lg` are 36, 44 and 52 points square — the same three heights the
labelled sizes stand at, so an icon button sits level with the text button beside it.

<Callout type="warn">
Always pair an `icon-*` size with an `accessibilityLabel`. There is no text for a screen reader to
fall back on.
</Callout>

## Loading

Use `isLoading` to compose a spinner in and block presses.

```tsx
<Button isLoading onPress={save}>Save</Button>
```

The spinner takes the place of the composed `Icon` rather than joining it, so nothing shifts when
work begins.

## Spinner placement

Use `spinnerPlacement` to choose which side the spinner takes, or `only` to replace the content.

```tsx
<Button isLoading spinnerPlacement="start">Save</Button>
<Button isLoading spinnerPlacement="end">Save</Button>
<Button isLoading spinnerPlacement="only">Save</Button>
```

<Callout title="Loading is not disabled">
`isLoading` blocks the press and announces the button as *busy*, but keeps full contrast. Pass
`isDimmedWhileLoading` to opt into the faded treatment.
</Callout>

## Press feedback

A button is a `Pressable`, so `feedback`, `haptic` and `pressedScale` are inherited. Only the
default differs — `scale`.

```tsx
<Button feedback="fade">Fade on press</Button>
<Button haptic="selection">With haptic</Button>
<Button pressedScale={0.92}>Deeper press</Button>
```

## Group

`Button.Group` joins several controls into one run. Each member squares the pair of corners
crossing a seam and overlaps its neighbour by a point, so two adjacent borders draw as one
hairline rather than two.

React Native has no sibling selector, so a member's place is worked out in JavaScript and
published through context rather than matched with CSS. A group of one is indistinguishable
from the control on its own.

<Preview id="button/group" />

```tsx
<Button.Group variant="outline">
  <Button onPress={archive}>Archive</Button>
  <Button onPress={report}>Report</Button>
  <Button onPress={snooze}>Snooze</Button>
</Button.Group>
```

The group owns the axes because it owns the shape. It sets every member's *step* — controls of
different heights do not join — while `variant`, `isDisabled` and `feedback` are defaults a member
may still override, so one member can disable itself inside a group that did not.

A member keeps its own *shape*, though, so a square button still works inside a run: an
`icon-md` member of an `sm` group comes out `icon-sm` — square, and the same height as everything
beside it.

```tsx
<Button.Group isDisabled size="sm" variant="outline">
  <Button>Save</Button>
  <Button variant="destructive">Discard</Button>
</Button.Group>
```

## Group orientation

A vertical run squares top and bottom instead of the ends. A horizontal one squares the inline
axis, so it flips under right-to-left layout without being told to.

<Preview id="button/group-orientation" />

```tsx
<Button.Group orientation="vertical" variant="outline">
  <Button accessibilityLabel="More" size="icon-md" onPress={increment}>
    <Icon icon={IconPlusMedium} />
  </Button>
  <Button accessibilityLabel="Fewer" size="icon-md" onPress={decrement}>
    <Icon icon={IconMinusMedium} />
  </Button>
</Button.Group>
```

Horizontal groups are content-width, because that is what a segmented control is. For a run that
fills its parent, put `w-full` on the group and `flex-1` on each member.

```tsx
<Button.Group className="w-full">
  <Button className="flex-1">Decline</Button>
  <Button className="flex-1">Accept</Button>
</Button.Group>
```

<Callout type="warn">
The parent has to have a definite width. Yoga resolves a percentage against the parent's content
box, so `w-full` inside a container that is itself content-sized falls back to the content width —
the group collapses onto its buttons and a `flex-1` member between them is squeezed to a few
points. It reads as though `w-full` were ignored; there was simply no width to take a percentage
of.
</Callout>

## Group separator

`Button.Group.Separator` draws a rule between two members — a split button. It takes no position
of its own, so the buttons either side of it are still the run's first and last and keep their
rounded outer corners. The member after it does not overlap either: a one-point rule under a
one-point overlap would be invisible.

<Preview id="button/group-separator" />

```tsx
<Button.Group>
  <Button onPress={save}>Save</Button>
  <Button.Group.Separator />
  <Button accessibilityLabel="More save options" size="icon-md" onPress={openMenu}>
    <Icon icon={IconChevronDownSmall} />
  </Button>
</Button.Group>
```

## Group text

`Button.Group.Text` is a member that says something rather than doing something. It draws the
button's own chrome, so its height, padding and corner match the buttons beside it exactly. It
falls back to `secondary` rather than `primary` when nothing names a variant — a chunk that
cannot be pressed should not wear the group's action paint.

<Preview id="button/group-text" />

```tsx
<Button.Group variant="outline">
  <Button accessibilityLabel="Fewer" size="icon-md" onPress={decrement}>
    <Icon icon={IconMinusMedium} />
  </Button>
  <Button.Group.Text>12 items</Button.Group.Text>
  <Button accessibilityLabel="More" size="icon-md" onPress={increment}>
    <Icon icon={IconPlusMedium} />
  </Button>
</Button.Group>
```

## Group with an input

An [Input](/docs/native/components/input) joins a run like any other member. Alone it draws the
generic corner ramp; joined, it takes the group's corner instead, so both ends of the row draw
the same arc.

<Preview id="button/group-input" />

```tsx
<Button.Group className="w-full">
  <Input className="flex-1" placeholder="Search components" variant="secondary" />
  <Button onPress={search}>Search</Button>
</Button.Group>
```

## Reading the button's state

Use `useButton()` to match the parent from a custom child, without prop drilling.

```tsx
import { useButton } from "delacour-react-native-ui/button";

function ButtonCount({ count }: { count: number }) {
  const { variant, size, isDisabled } = useButton();
  // …
}
```

### Exports

```tsx
import {
  BUTTON_VARIANTS,
  BUTTON_SIZES,
  BUTTON_LABEL_SIZES,
  BUTTON_ICON_SIZES,
  BUTTON_SPINNER_PLACEMENTS,
  BUTTON_GROUP_ORIENTATIONS,
  BUTTON_GROUP_POSITIONS,
  BUTTON_FOREGROUND_TOKEN,
  buttonVariants,
  resolveGroupPositions,
  resolveGroupSeams,
} from "delacour-react-native-ui/button";
```

`BUTTON_SIZES` is every value `size` accepts. `BUTTON_LABEL_SIZES` and `BUTTON_ICON_SIZES` are the
two families it is composed from — map one when a list should hold only labelled buttons, or only
square ones.

`BUTTON_FOREGROUND_TOKEN` maps each variant to the theme token its icons and text are drawn in.
`buttonVariants` is the `tv()` slot set — useful when building a component that has to match a
button exactly.

`resolveGroupPositions` and `resolveGroupSeams` are the pure walks behind a group: given which
children are members, they return each one's place in the run and which ones overlap their
neighbour. They take arrays of booleans rather than children, so they stay free of React and the
whole matrix is unit-tested.
