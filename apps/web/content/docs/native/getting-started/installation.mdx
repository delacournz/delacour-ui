The CLI and the package hold the same components. The CLI copies the source into your repository
so you own `button.tsx`; the package is upgraded with `bun update`. Start with the CLI — it does
the wiring below for you.

## Use the CLI

<InstallTabs commands={[{ verb: "dlx", packages: ["delacour@alpha init --install"] }]} />

`init` writes `native-components.json`, wraps your Metro config with Uniwind's transform, adds the
`@source` globs to your Tailwind entry, copies the theme and the root provider in, and installs
what they need. Then add components by name:

<InstallTabs commands={[{ verb: "dlx", packages: ["delacour@alpha add button input field --install"] }]} />

Two things remain yours: importing the CSS and mounting the provider — both shown in
[Mount the provider](#mount-the-provider), and both done for you on the
[Quick start](/docs/native/getting-started). See [the CLI docs](/docs/native/cli) for what `init`
will and will not touch, and [Monorepos](/docs/native/cli/monorepo) for a shared package.

## Install the package

<LibraryInstall />

The library ships raw `.tsx`. Uniwind's transform has to run in **your** app's Metro pipeline, so a
precompiled build would arrive with its classNames already dead — which is also why its native
dependencies are peers rather than dependencies. Two copies of a native module register twice and
break at runtime. The list above is derived from the components' own imports, so it is complete.

<Callout type="warn" title="Do not install native modules with your package manager">
`bun add react-native-reanimated` fetches the newest release, which on any older SDK is a package
that fails at the linker rather than at install time. `expo install` asks the SDK what it supports.
</Callout>

Three peers are optional, resolved only if you import the subpath that needs them:

| Package | Needed by |
| --- | --- |
| `@legendapp/list` | `Screen.LegendList`, `Screen.ChatList` (the default `legend` variant) |
| `expo-router` | `delacour-react-native-ui/expo/navigation-theme` |
| `react-native-screens` | native stack navigation |

### Import from subpaths

There is no package-wide barrel, and that is deliberate: it is what lets an app skip resolving
optional peers it never uses.

```tsx
import { Button } from "delacour-react-native-ui/button";
import { Icon } from "delacour-react-native-ui/icon";
import { IconHeart } from "delacour-react-native-ui/icons/central";
```

```tsx
// This does not exist, and will not be added.
import { Button } from "delacour-react-native-ui";
```

### Wire up the CSS

On the package path, import the library's styles into your app's Tailwind entry and point
Tailwind's scanner at the package source. The CLI writes this block itself.

```css title="src/styles/global.css"
@import "tailwindcss";
@import "uniwind";
@import "delacour-react-native-ui/styles";

@source "../**/*.{ts,tsx}";
@source "../../node_modules/delacour-react-native-ui/src";
```

<Callout type="warn" title="In a workspace, use the real path">
Bun symlinks workspace packages, and Tailwind's scanner **cannot follow symlinks**. In a monorepo,
point the second `@source` at the package's actual directory — `../../../../packages/native-ui/src`
or wherever it lives — or every class the library uses is silently dropped from your production
build.
</Callout>

Then wrap Metro, **outermost**, so `className` compiles:

```js title="metro.config.js"
const { getDefaultConfig } = require("expo/metro-config");
const { withUniwindConfig } = require("uniwind/metro");

const config = getDefaultConfig(__dirname);

module.exports = withUniwindConfig(config, {
  cssEntryFile: "./src/styles/global.css",
  dtsFile: "./src/uniwind-types.d.ts",
});
```

## Manual setup

Every component page carries a **Manual** tab listing the exact packages and files that component
needs, each linked to its source — [Button](/docs/native/components/button) is the one to look at
first. `delacour view button` prints the same list in your terminal.

## Mount the provider

Whichever path you took, the root layout does two things: imports the CSS as its **first
statement**, and wraps everything in the provider, once.

```tsx title="app/_layout.tsx"
import "@/styles/global.css";
import { DelacourProvider } from "delacour-react-native-ui/provider";
import { Stack } from "expo-router";

export default function RootLayout() {
  return (
    <DelacourProvider>
      <Stack screenOptions={{ headerShown: false }} />
    </DelacourProvider>
  );
}
```

On the CLI path the import is `@/components/ui/provider`, and `init` has already copied it in.

`DelacourProvider` is five layers, outermost first: `GestureHandlerRootView` → `SafeAreaProvider` →
`KeyboardProvider` → `<KeyboardStateSync />` beside the children → `BottomSheetModalProvider` around
them. The order is load-bearing — see [Provider](/docs/native/getting-started/provider) for what
breaks at each layer.

<Callout type="warn">
Without the CSS import every component renders unstyled. Without the gesture root, presses stop
landing. Both silently — no error, no warning. `delacour doctor` checks for each.
</Callout>

### Composing the layers by hand

Only if your app already has a root stack of its own. `<KeyboardStateSync />` is **required**, not
optional polish, and must be a child of `KeyboardProvider`.

```tsx
import { BottomSheetModalProvider } from "@gorhom/bottom-sheet";
import { KeyboardStateSync } from "delacour-react-native-ui/hooks/use-keyboard-state-sync";
import { GestureHandlerRootView } from "react-native-gesture-handler";
import { KeyboardProvider } from "react-native-keyboard-controller";
import { initialWindowMetrics, SafeAreaProvider } from "react-native-safe-area-context";

<GestureHandlerRootView>
  <SafeAreaProvider initialMetrics={initialWindowMetrics}>
    <KeyboardProvider>
      <KeyboardStateSync />
      <BottomSheetModalProvider>{children}</BottomSheetModalProvider>
    </KeyboardProvider>
  </SafeAreaProvider>
</GestureHandlerRootView>;
```

## Verify

```tsx title="app/index.tsx"
import { Button } from "delacour-react-native-ui/button";
import { useState } from "react";
import { View } from "react-native";

export default function Index() {
  const [count, setCount] = useState(0);

  return (
    <View className="flex-1 items-center justify-center bg-background">
      <Button onPress={() => setCount(count + 1)}>Pressed {count} times</Button>
    </View>
  );
}
```

A string child is wrapped in a `Button.Label` for you. If the button renders but does not respond,
the gesture root is missing above it. If it renders as plain text on white, the CSS import is
missing or not first.
