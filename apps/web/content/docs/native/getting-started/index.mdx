**Components you compose, not components you configure.** You build a button out of a label and an
icon, not out of fifteen boolean props.

- **Composition over booleans:** icons are children. A parent publishes size and colour to its
  subtree, so a bare `<Icon>` comes out matching the label beside it.
- **One scale, shared:** `Icon` and `Spinner` resolve `md` to the same edge length. A `Checkbox`
  reads that scale two steps up rather than minting its own.
- **Themed by CSS variables:** components name `bg-background`, never a raw palette colour and never
  a `dark:` prefix.
- **Ships as source:** no build step. Uniwind's transform runs in your app's Metro pipeline.
- **Two deliveries, one library:** install the package, or copy the source in with the CLI.

```tsx
import { Button } from "@delacour/native-ui/button";
import { Icon } from "@delacour/native-ui/icon";
import { IconArrowRight } from "@delacour/native-ui/icons/central";

<Button haptic="selection" onPress={next}>
  <Button.Label>Continue</Button.Label>
  <Icon icon={IconArrowRight} />
</Button>;
```

The icon above names no size and no colour. The button publishes both to its subtree.

## Composition over booleans

Every component takes children where a lesser one would take a prop. Icons are composed in, loading
swaps the icon it replaces rather than joining it, and a slot is a component rather than a
`renderX` callback.

*A boolean prop is a decision you made for every future caller. A child is one they make themselves.*

## One scale, shared

Sizes are semantic tokens — `size-icon-md`, `h-button-md`, `text-input-md` — declared once in
`tokens.css`. A component indexes that scale at its own step name rather than restating a number,
which is what makes a button's loading swap cost no layout: the spinner and the icon it replaces are
drawn at the same token.

[Sizing](/docs/native/getting-started/sizing) has the whole ladder.

## Themed by CSS variables — shadcn's

The palette is shadcn's, name for name, in shadcn's two-layer shape. Bring the theme out of your web
app and these components wear it:

```bash
npx delacour@alpha theme ./src/app/globals.css
```

Components reference semantic names and never a `dark:` prefix, so swapping the variables swaps the
theme — including the slab a native stack paints behind a push, which no `contentStyle` can reach.

[Theming](/docs/native/getting-started/theming) covers both, and the navigator case.

## Ships as source

There is no build step and no package-wide barrel. Uniwind compiles `className` in a Metro
transform, so a precompiled build would arrive with its classNames already dead — and granular
export subpaths are what let an app skip resolving optional peers it never uses.

*Import `@delacour/native-ui/button` and nothing keyboard-related resolves.*

## Two deliveries, one library

Install the package and upgrade it, or run the CLI and own the files. The components are identical —
the CLI copies the same source the package ships — and every component page carries both commands

## Scope

React Native only — iOS and Android, Expo or bare. No navigation dependency and no form-library
dependency. Where a component needs to talk to a router it takes a callback instead:
`Screen.Navbar.BackButton` has an `onPress`, not a `router.back()`.
