# @delacour/playground — native-ui's Harness and Gallery

An Expo app whose only job is to render `@delacour/native-ui` on a device. It is
not a product and has no users. Every screen exists to make one component's
behaviour visible, and step 5 of
[Adding a component](../../packages/native-ui/AGENTS.md#adding-a-component)
requires a route here for anything new.

## Stack

- **Expo 57** with **expo-router** — file-based routing, `expo-dev-client`
- **Uniwind** — the same styling layer the library uses, configured in Metro
- **`@delacour/native-ui`** as a workspace source dependency, not a build
- **Central Icons** — the icon set, same as the library

## Commands

```bash
bun dev                    # ensure-prebuild, then expo start --dev-client --clear, port 8088
bun start                  # the same, on Expo's default port
bun ios                    # ensure-prebuild, then expo run:ios --device --port 8088
bun android                # ensure-prebuild, then expo run:android --device --port 8088
bun run prebuild           # expo prebuild — regenerate ios/ and android/
bun run icons              # rasterise the app icon from assets/icon-source.svg
bun run check              # Biome
bun run typecheck          # tsc --noEmit
```

**Never launch against Expo Go.** The app depends on native modules Expo Go does
not carry — Reanimated worklets, Gesture Handler, keyboard-controller, Pulsar
haptics. `scripts/ensure-prebuild.ts` guards `dev`, `ios` and `android`: if
`ios/` or `android/` is missing it stops and tells you to run `bun expo prebuild`.
Both directories are gitignored, so a fresh clone always prebuilds once.

**Port 8088, not 8081.** `dev`, `ios` and `android` all pin it, so a Metro left
running from another project does not silently serve this one.

## Directory structure

```
src/
├── app/                          expo-router routes
│   ├── _layout.tsx               DelacourProvider + NavigationTheme + the global.css import
│   ├── index.tsx                 the component index — a ListGroup of every gallery
│   └── (components)/             one route per component, grouped without a path segment
├── components/
│   ├── gallery-screen.tsx        GalleryScreen — the frame every gallery sits in
│   ├── section.tsx               Section — a labelled block within a gallery
│   └── delacour-mark/            the wordmark, rendered by its own gallery
├── hooks/use-transient-loading.ts
├── styles/global.css             the Tailwind + Uniwind + library entry
└── uniwind-types.d.ts            generated by Uniwind's Metro plugin — do not edit
```

## Routes

`(components)` is a **route group**: the parentheses keep it out of the URL, so
the file `(components)/button.tsx` is the route `/button`.

A component's gallery takes one of two shapes, and which one depends on whether
it fits on a page:

- **A single file** — `(components)/button.tsx` → `/button`. Most components.
- **A folder with an `index.tsx` and one file per facet** —
  `(components)/tabs/{index,variants,sizes,swipe,scrolling,composition}.tsx` →
  `/tabs` plus `/tabs/variants` and the rest. The `index.tsx` is itself a
  `ListGroup` of the facets. `screen/`, `tabs/`, `input/`, `field/` and
  `bottom-sheet/` use this shape, because a component with five independent
  behaviours on one scroll is a page nobody reads to the bottom of.

Start with a single file. Split it the moment the page needs a second heading
that is really a second subject.

## Adding a gallery page

1. `src/app/(components)/{name}.tsx`, wrapping the body in `GalleryScreen` and
   grouping demos with `Section`.
2. **Add a row to `COMPONENTS` in `src/app/index.tsx`** — `href`, `icon`,
   `title`, `description`. The array is alphabetical by title. A gallery with no
   row is a page only a URL reaches, and nobody types URLs on a phone.
3. Pick the icon from `@delacour/native-ui/icons/central`. Central Icons only,
   the same rule the library follows.
4. Run it on a simulator and actually interact with it. That is the whole point
   of this app — `bun test` in the library cannot render anything.

**`GalleryScreen` carries the title on the back button**, not above the content,
so the first row starts at the top of the viewport. It is deliberately a
`Screen.ScrollArea` rather than a static body: that exercises the tap-versus-scroll
gesture conflict, which is what most often breaks in a component built on the
Gesture API. Pass `keyboardAware` only for a gallery holding a text field.

## `_layout.tsx` is `DelacourProvider`'s only test

`DelacourProvider` has no gallery and no row on the index, because every route in
this app renders downstream of it — a stronger check than a readout page could
be. It is **mounted with no props on purpose**: the defaults are what a consuming
app gets, so a regression in one of them shows up here first.

Three things in that file are load-bearing:

- **The `global.css` import must stay the first statement, and must stay in
  `_layout.tsx`.** Importing it from the registered entry (`index.ts`) breaks
  Uniwind's hot reload and forces a full reload on every edit.
- **`NavigationTheme`** hands the navigator the library's tokens. Without it
  React Navigation's pale default paints the slab visible between cards during a
  push — see [Theming](../../packages/native-ui/AGENTS.md#theming).
- **`SystemBackground`** paints the native root view beneath the whole React
  tree. `app.config.ts` carries only one static `backgroundColor` and cannot
  follow a theme the user changes at runtime; this can, keyed on the same token.

Which routes prove which layer: `/pressable` for the gesture root,
`/screen/navbar` for the insets, `/screen/form` for the keyboard.

## Styling

`src/styles/global.css` imports Tailwind, Uniwind and the library's styles, then
declares two `@source` scans:

```css
@source "../**/*.{ts,tsx}";
@source "../../../../packages/native-ui/src";
```

**The second must be the real workspace path, never a `node_modules` one.** Bun
symlinks workspace packages and Tailwind's scanner cannot follow symlinks, so the
library's classes would be silently dropped from production builds — a bundle
that looks right in dev and unstyled when shipped.

## Metro

`metro.config.js` does three things no default config does, and each has a
failure attached:

- **`watchFolders` + `nodeModulesPaths` reach the workspace root**, because
  `native-ui` is consumed as source. `disableHierarchicalLookup` stops Metro
  walking up and finding a second copy on its own.
- **`extraNodeModules` pins eight native modules to the root copy.** Bun
  materialises a second copy under this app, and two registrations of a native
  module break at runtime.
- **`withUniwindConfig` must stay the outermost wrapper**, taking `global.css`
  as its entry and generating `src/uniwind-types.d.ts`.

`tsconfig.json` pins `react-native` to the root copy for the same reason, in
TypeScript's terms — see [packages/tsconfig](../../packages/tsconfig/AGENTS.md).

## Conventions

- **`biome.jsonc` turns `useFilenamingConvention` off for `src/app/**`**, because
  Expo Router derives route names from filenames and `_layout`, `[id]` and
  `+not-found` are not kebab-case. Everything outside `src/app` is kebab-case.
- **This app extends `expo/tsconfig.base`**, not `@delacour/tsconfig`. Expo's
  base carries the resolver settings its Metro pipeline expects.
- **No comments inside JSX.** The explanation goes in the component's doc comment
  or above the `return`.
- The app icon is generated — edit `assets/icon-source.svg` and run
  `bun run icons`, never the PNGs. `ios/` and `android/` are gitignored, so an
  `app.config.ts` change reaches a device only through `prebuild` and a rebuild.
