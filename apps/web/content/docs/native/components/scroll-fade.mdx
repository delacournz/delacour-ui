## Usage

```tsx title="components/day-strip.tsx"
import { useScrollSource } from "@/hooks/use-scroll-source";
import { ScrollFade } from "@/components/ui/scroll-fade";
import { Text } from "@/components/ui/text";
import { View } from "react-native";
import Animated from "react-native-reanimated";

const DAYS = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"];

export default function DayStrip() {
  const { source, scrollProps } = useScrollSource({ orientation: "horizontal" });

  return (
    <ScrollFade scrollSource={source} size={40}>
      <Animated.ScrollView
        contentContainerClassName="gap-3 px-4"
        horizontal
        showsHorizontalScrollIndicator={false}
        {...scrollProps}
      >
        {DAYS.map((day) => (
          <View className="h-28 w-28 items-center justify-center rounded-xl bg-secondary" key={day}>
            <Text.Label>{day}</Text.Label>
          </View>
        ))}
      </Animated.ScrollView>
    </ScrollFade>
  );
}
```

ScrollFade overlays the scrollable; it never wraps it or touches its props. The scrollable reports
its offset and sizes through the props `useScrollSource` returns, and the fade reads them on the UI
thread — a scroll renders nothing in React.

## Inside a Screen

A `Screen` publishes its own body as a scroll source, so a fade inside one needs no wiring at all.
Give it `flex-1` so it fills the body.

```tsx
<Screen>
  <ScrollFade className="flex-1">
    <Screen.ScrollArea>{rows}</Screen.ScrollArea>
  </ScrollFade>
</Screen>
```

## useScrollSource

Use it for any scrollable that is not a `Screen` body — a card row, a list in a `Card`, a sheet body,
a chip strip. Spread `scrollProps` onto an `Animated.ScrollView`, `Animated.FlatList` or similar.
The axis is the source's, fixed when you create it, so ScrollFade has no `orientation` prop to
disagree with it.

<Preview id="scroll-fade/horizontal-cards" />

```tsx
const { source, scrollProps } = useScrollSource();                             // vertical
const { source, scrollProps } = useScrollSource({ orientation: "horizontal" }); // a row
```

`ScrollSourceProvider` shares one source with everything beneath it, so a fade several components
down can find it without a prop.

## Name the surface

The fade is a colour, not a mask. Over a card, pass the card's colour; the default `background` over
a card reads as a grey band. `color` takes a theme token or a literal.

<Preview id="scroll-fade/vertical-list" />

<Preview id="scroll-fade/on-a-surface" />

```tsx
<ScrollFade color="card" scrollSource={source}>
  <Animated.ScrollView {...scrollProps}>{rows}</Animated.ScrollView>
</ScrollFade>
```

## Edges and distance

`edges` picks which ends fade. `fadeInDistance` is how many points of travel an edge takes to arrive —
`0` makes it a step — and is separate from `size`, the depth of the band. `insetStart` / `insetEnd`
hold a band in from its edge, under a bar the fade cannot see.

<Preview id="scroll-fade/single-edge" />

```tsx
<ScrollFade edges="end" scrollSource={source} />
<ScrollFade fadeInDistance={0} scrollSource={source} />
<ScrollFade insetStart={56} scrollSource={source} />
```

## ScrollFade or Screen.ScrollShadow

|  | ScrollFade | Screen.ScrollShadow |
| --- | --- | --- |
| Where | Any scrollable, any container | A Screen body |
| Axis | Vertical or horizontal | Vertical |
| Aware of the navbar and footer | No — use `insetStart` / `insetEnd` | Yes, it measures them |
| Solid cover bands | No | `coverTop` / `coverBottom` |

## Accessibility

The bands are purely visual: `pointerEvents="none"`, hidden from assistive technology, and the
wrapper adds nothing to the accessibility tree. The opacity follows the user's own finger and
nothing moves on its own, so there is nothing for reduce motion to still.

## Notes

- An edge is drawn only while there is content past it. A list too short to scroll draws neither.
- Before a source has measured anything the end edge is drawn: a `Screen` learns its sizes from
  the first scroll event, and a tall body should show its end fade at rest. `useScrollSource`
  measures on layout, so a short list loses the end fade within a frame.
- `start` and `end` follow the scroll axis in layout space; they do not flip under right-to-left.
- A `Screen` nested inside another reports to the outer one, so a fade over a nested Screen's
  body follows the outer scrollable. Pass a `scrollSource` there.
